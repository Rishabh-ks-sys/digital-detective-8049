### Task 6.1 — Basic Git Workflow

| Git operation | Explanation |
|---|---|
| Check repository status | Shows modified, staged, and untracked files. |
| Stage selected changes | Selects changes for the next commit. |
| Create a commit | Records staged changes with a message. |
| View commit history | Displays previous commits and their details. |

**Staging vs committing:** Staging selects which changes should be included. Committing records those selected changes in the repository history.

### Task 6.4 — Git Command Glossary

| Command | Purpose |
|---|---|
| `git init` | Initializes a repository. |
| `git status` | Checks repository status. |
| `git add` | Stages selected changes. |
| `git commit` | Records staged changes. |
| `git log` | Displays commit history. |
| `git branch` | Lists branches. |
| `git branch name` | Creates a branch. |
| `git switch name` | Switches branches. |
| `git push` | Publishes changes to a remote repository. |
| `git pull` | Retrieves and integrates remote changes. |

## 4. My Understanding

Git tracks changes in files and helps maintain a history of a project. GitHub hosts repositories online and makes collaboration easier. Branches allow developers to work on separate versions of a project, while Pull Requests allow changes to be reviewed before merging.
